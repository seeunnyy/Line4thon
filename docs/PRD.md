# PRD.md

## Problem
다이어트가 무너지는 건 의지 부족이 아니라, 회식·여행·명절처럼 예정되어 있었지만 설계되지 않은 이벤트, 그리고 일탈을 전체 실패로 오인하는 인지왜곡 때문이다.

## Target User
N차 재도전자 — 다이어트를 3회 이상 시도했다가 중단한 경험이 있고, 기존 다이어트 앱에 대한 신뢰가 낮은 20~30대

## Core Value
예정된 이벤트를 미리 시뮬레이션해 무너짐 자체를 방지하고, 무너지더라도 계획된 복귀로 이어준다.

## Platform
스마트폰 세로 화면 기준의 모바일 서비스. 모바일 웹앱으로 구현하고 시연은 실제 폰에서 한다.

## Core Features
- 이벤트 시뮬레이터 (표시체중 vs 실제지방 이중 그래프)
- AI 재개 코치 (준비도 체크인 → 단계적 복귀)
- 일탈 리프레이밍 개입
- 재도전 경험치화
- 내 아바타 (동반자 캐릭터) — 온보딩에서 사용자가 만든 아바타가 표정·소지품으로 반응한다
- 날씨 UI
- 온보딩 (정보 입력 + 아바타 설정)
- 기록 (이벤트 대응 기록)

## Core Flow
스플래시 → 온보딩 → 홈 → 예보(이벤트 등록·결과) → 이벤트 종료 후 체크인 → 기록에 누적

## Priorities
- P0 (없으면 데모 불가): 온보딩(정보 입력 + 아바타 프리셋 선택) → 홈(아바타 표시) → 이벤트 등록 → 시뮬레이션 결과 → 재개 체크인. 마이페이지의 "데이터 초기화"(시연 안정성)
  - 대응 Core Features: 온보딩, 내 아바타(동반자 캐릭터), 이벤트 시뮬레이터, AI 재개 코치
- P1: 날씨 UI, 일탈 리프레이밍, 아바타 꾸미기(카테고리 탭), 기록 탭(지난 이벤트 타임라인), "데모 데이터 불러오기"
  - 대응 Core Features: 날씨 UI, 일탈 리프레이밍 개입, 기록
- P2: 아바타의 표정·소지품 반응, 재도전 경험치 표시, 홈 화면에 추가(PWA)
  - 대응 Core Features: 내 아바타(동반자 캐릭터)의 세부 반응 동작, 재도전 경험치화
- 원칙: 시간이 부족하면 P2부터 버린다. P0가 끝나기 전에는 P1/P2에 착수하지 않는다.

## Non-goals
- 결제/구독 기능
- 복잡한 소셜 인증
- 실시간 협업
- 대용량 파일 업로드
- InBody·웨어러블 등 다중 외부 연동 (2단계 이후)
- 네이티브 앱 빌드·앱스토어 배포 (2단계 이후)
- 푸시 알림 (2단계 이후). 알림형 기능은 앱 실행 시 홈 카드·말풍선으로 대체한다

## Success Criteria
- 해커톤 데모 시연 가능한 수준의 동작하는 MVP
- 온보딩 → 홈 → 이벤트 등록 → 시뮬레이션 → 재개 체크인까지 핵심 플로우 1개 완주
- 실제 스마트폰에서 시연 가능
