# DESIGN.md

## Design Goal
반복되는 다이어트 실패에 지친 사용자에게 부담을 주지 않는, 차분하고 신뢰감 있는 모바일 앱 화면.

## Brand
- 이름: **Bodycast** (Body + Forecast). 기존 "날씨예보" 은유를 그대로 잇는다.
- 재도전을 해도 그 전의 과정은 실패가 아닌 기록으로 남는다.
- 일정이 있는 날, 몸무게를 예측할 수 있도록 AI 시뮬레이션을 제공한다 (내부 메시지. 화면에는 "예보"라는 표현을 쓴다).
- 내 아바타와 함께 성장한다.

## Visual Tone
- Calm (경쟁·보상 요소 없이 잔잔하게)
- Friendly
- Soft 3D-like
- Sky-blue — 하늘·날씨 은유와 연결되는 블루 계열을 주조색으로 삼는다
- Minimal
- Easy to scan
- Card-based when useful
- "날씨예보" 은유 — 체중 변화를 날씨처럼 자연스러운 변동으로 표현

### 레퍼런스 요약 (이미지 우선, 아래는 요약)
- 캐릭터가 화면의 주인공이다. 홈은 "큰 캐릭터 + 말풍선 + 아래 카드" 구성 (동네 걷기 앱 홈 유형)
- 대화형 온보딩: 큰 질문 한 줄 → 캐릭터 → 하단 고정 전체폭 버튼 하나. 진행 표시는 상단 원형/점 (아바타 선택 화면 유형)
- 캐릭터는 2~3등신의 부드러운 3D 느낌이고, 흰색·파스텔 바탕에 선명한 블루가 포인트다 (레퍼런스 이미지 자체의 색감. 우리 토큰은 이를 절제해 파스텔 톤으로 가져온다 — 아래 디자인 토큰 참고)
- 배경은 부드러운 그라데이션/일러스트 (해 질 녘 보랏빛, 파란 스튜디오 등)
- 아바타 꾸미기: 상단 실시간 미리보기 + 카테고리 탭(얼굴형, 헤어, 표정, 의상 등) + 선택 테두리가 있는 그리드 + 우상단 "완료"
- 큰 라운드 카드, 큰 숫자, 넉넉한 여백, 하단 전체폭 라운드 버튼

**가져올 것**: 위 레이아웃 문법과 둥글고 부드러운 캐릭터 느낌

**가져오지 않을 것**:
- 코인·포인트·보물상자·"받기" 버튼 같은 보상/적립 구조 (기존 "경쟁·보상 없음" 원칙이 우선)
- 걸음 수·랭킹 같은 수치 압박 요소
- 레퍼런스의 캐릭터·로고·일러스트를 그대로 따라 그리는 것 (톤만 참고하고 캐릭터·에셋은 자체 제작)

## Mobile
- 기준 화면 390×844, 지원 폭 360~430px, 세로 고정. 상태바와 홈 인디케이터는 OS 영역이라 그리지 않는다.
- 세이프에어리어 처리: `viewport-fit=cover`와 `env(safe-area-inset-*)`를 쓴다. 하단 탭바와 하단 고정 버튼이 홈 인디케이터를 가리지 않는다.
- 화면 높이는 `100vh` 대신 `dvh`를 쓴다 (모바일 브라우저 주소창 대응).
- 터치 영역은 최소 44×44px. 주요 행동 버튼은 엄지가 닿는 하단에 전체폭으로 둔다.
- 입력 필드 글자는 16px 이상 (iOS Safari 자동 확대 방지). 숫자 입력은 숫자 키패드(`inputmode`)를 쓰고, 키보드가 올라와도 입력창과 버튼이 가려지지 않게 한다.
- 확대/축소를 막지 않는다 (접근성).
- hover에 의존하지 않는다. 탭·스와이프·바텀시트 중심이다 (아바타 캐러셀은 스와이프 + 점 표시).
- 이중 그래프는 폭 약 350px에서도 가로 스크롤 없이 읽히게 하고, 값은 탭으로 확인한다. 그래프 글자는 12px 이상.
- 애니메이션은 가볍게 하고 `prefers-reduced-motion`을 존중한다.
- 데스크톱에서는 390px 폰 프레임, 모바일은 360~430px 유동.
- 뒤로(‹)·닫기(×) 같은 표준 이동 아이콘은 "icon-only 금지" 규칙의 예외로 허용하되 접근성 라벨을 필수로 한다. 나머지 액션은 기존대로 텍스트 라벨을 쓴다.
- "홈 화면에 추가"(PWA manifest)는 P2. 서비스워커·오프라인 기능은 만들지 않는다.

## Character & Avatar Rules
- 캐릭터는 하나(내 아바타)이고, 표정·자세·말풍선·소지품으로만 반응한다. 별도 마스코트는 만들지 않는다.
- 아바타 외형은 체중·시뮬레이션 결과와 무관하게 고정이다. 체형·체중 관련 옵션은 없고(몸 실루엣 1종 고정), 커스터마이징은 얼굴형·헤어·피부톤·표정·의상·소품만 허용한다.
- 구현은 2D 레이어 합성(PNG)이 기본이고, 몽실이 자체의 움직임만 직접 짠 WebGL 2.5D 엔진이다(아래 모션). 3D 라이브러리(three.js 등)와 3D 모델 파일은 쓰지 않는다 (불필요한 의존성 추가 금지 원칙).
- **몽실이** (내 아바타, 흰 곰). 몸은 고정이고 날씨 예보(맑음·흐림·소나기)에 따라 표정과 소품만 달라진다.
  - 맑음: 선글라스 + 해 / 흐림: 눈 감은 미소 + 구름 / 소나기: 놀란 표정 + 파란 우산 + 빗방울. 크로스백은 세 모습 공통이다.
  - 에셋은 팀이 만든 3컷 렌더(맑음·흐림·소나기)에서 배경을 지운 투명 PNG(`public/avatar/`)다. 원본 렌더는 저장소에 두지 않는다.
    - `mongsil-sunny|cloudy|rain.png`: 전신(소나기는 우산 포함). 세 모습이 590×672 공통 캔버스에서 몸 위치·크기가 같아 날씨가 바뀌어도 몸이 흔들리지 않는다.
    - `prop-sun.png`, `prop-cloud.png`, `prop-drop.png`: 따로 움직이는 소품(해·구름·빗방울).
    - `mongsil-sunny|cloudy|rain-depth.png`: 2.5D 움직임용 깊이맵(8비트 흑백, 절반 해상도, 값 = 높이(px)×2). 실루엣 거리로 둥글게 부풀리고 얼굴·팔·가방·발을 볼록하게 더했고, 소나기의 우산은 평평하게 앞에 둔다. 경계 밖으로도 값을 늘려 둬서 가장자리가 찢어지지 않는다.
    - `rain-patch|browL|browR|eyeL|eyeR.png`: 소나기 얼굴 부품(눈·눈썹을 떼고 피부를 메운 패치). 깜빡임·눈동자·눈썹 움직임용이고, 기본 자세에서 합치면 원본 렌더와 같다.
    - `face-sunny|cloudy|rain.png`: 원형 아바타용 얼굴 크롭(256×256). 기본은 흐림(차분한 미소).
  - 전신은 `components/ui/Mongsil.tsx`(홈 히어로·아바타 꾸미기 미리보기·온보딩. 몸통은 `MongsilBody.tsx`), 원형은 `components/ui/Avatar.tsx`(헤더·코치 카드·빈 상태·기록·마이페이지)가 쓴다. 원형 아바타의 크기와 배지 좌표는 UI-SPEC.md 그대로이고, 얼굴 뒤 바탕만 하늘색 그라데이션(#D7E6FA→#EDF3FD)이다(빈 자리였을 때의 #F0EFED는 이미지 로딩 전 바탕으로만 남는다).
  - 모션 — 몽실이 자체(2.5D): 렌더 한 장을 격자 메시로 깔고 깊이맵으로 볼록하게 만든 뒤, 고개 돌림(요)·끄덕임(피치)·갸웃(롤)·젤리 기울기·발 기준 스쿼시&스트레치·뜀으로 움직인다. 원근 없는 정사영이라 기본 자세는 원본 이미지와 똑같다. 진짜 3D 모델이 아니라 그림에 입체감을 입힌 것이라 각도는 ±7° 안쪽으로만 쓴다(일부러 작은 움직임). 코드는 `components/ui/mongsil/`(`layout.ts` 좌표, `motion.ts` 날씨별 안무, `engine.ts` WebGL)와 `MongsilBody.tsx`(React 연결).
    - 맑음: 3.4초 주기로 통통 뜀(12px) + 고개를 천천히 좌우로, 5초마다 선글라스가 반짝. 흐림: 4~8초 주기로 숨 쉬듯 흔들리고 고개를 살짝 끄덕임. 소나기: 6초 주기로 깜짝(살짝 뜀 + 눈썹 올라감) → 두리번(눈동자 이동) → 떨림, 3.3초마다 눈 깜빡임.
    - 탭하면 한 번 통 뛴다(장식 반응이라 버튼이 아니다). 발 밑 그림자는 뜀에 맞춰 작아지고 옅어진다.
    - 소품은 그대로 CSS다: 해는 둥실, 구름은 좌우로, 빗방울은 떨어지며 사라진다(tailwind `mongsil-*`).
    - 멈추는 조건: `prefers-reduced-motion`, `animate={false}`(온보딩에서 지금 안 보이는 카드), 화면 밖, 탭이 가려짐. 시간은 움직인 동안만 흘러서 다시 시작해도 툭 튀지 않는다.
    - 대체(폴백): 서버가 그리는 정지 `<img>`가 항상 밑에 있다. WebGL을 못 쓰거나(컨텍스트 생성 실패·유실) 로딩에 실패하면 이 그림에 예전 CSS 숨쉬기(몸이 발 기준으로 아주 조금 커졌다 줄어듦)만 남는다. 캔버스는 첫 프레임이 그려진 뒤에 정지 그림을 대신한다. `prefers-reduced-motion`이면 캔버스 자체를 만들지 않는다.
    - 성능: 메시 6px 격자(약 6~9천 정점), 그리기 1~6회/프레임, 버퍼 배율 1.5~2배. 보이는 카드만 그린다.
  - 발 밑 그림자는 CSS 타원이다(원본의 바닥 그림자는 뺐다).
  - 꾸미기 항목(얼굴형·헤어·의상·소품)용 에셋은 아직 없다. 아바타 꾸미기 화면의 선택지는 빈 타일이고 미리보기만 몽실이다.
- 말풍선 문구는 docs/LLM.md의 안전 규칙을 따른다.

## Navigation
하단 탭바 (아이콘과 텍스트 라벨을 항상 함께 표시):
- 홈
- 예보: 이벤트 등록 → 시뮬레이션 결과(이중 그래프)를 담는다. 화면 카피에는 "AI 시뮬레이션"이라는 표현을 쓰지 않는다
- 기록 (P1): 지난 이벤트 타임라인(이벤트·예보·체크인 여부). 재도전을 실패가 아닌 기록으로 남기는 브랜드 메시지를 담당한다. "이벤트 대응 경험" 누적 표시는 P2
- 마이페이지: 프로필, 아바타 꾸미기, 설정

- 재개 체크인은 별도 탭 없이, 이벤트 종료 후 홈 카드와 예보 상세에서 진입한다.
- UI 시안 단계부터 홈·예보·기록·마이페이지 4개를 모두 그린다. 기록 화면의 데이터·로직은 P1.
- 노출 규칙: 탭바는 탭 최상위 화면에서만 보이고, 온보딩·이벤트 등록·결과·체크인 같은 하위 흐름에서는 숨긴다.
- 하단 고정, 세이프에어리어 반영.

## Screens
화면 시안 완료(로직 없음): 스플래시·정보 입력·아바타 선택·홈·예보(목록/등록/결과)·체크인·기록·마이페이지·아바타 꾸미기. 화면별 상태 미리보기는 `/dev` 색인에서 볼 수 있다.

- **스플래시/인트로**: 로고 + "시작하기" 버튼. 기존 "랜딩 페이지"를 대체한다.
- **정보 입력**: 닉네임, 재도전 횟수(N차) 필수. 키, 현재 체중은 선택.
- **아바타 설정**: "몽실이가 날씨를 예보해요" — 몽실이 세 가지 모습(맑음·흐림·소나기)을 보여주는 스와이프 캐러셀(고르는 화면이 아니라 소개 화면) → "몽실이와 시작하기"로 홈 진입, "꾸며서 시작할래요"로 꾸미기 진입. 이후 앱 전체에서 몽실이가 등장한다. (프리셋 5장 선택 → 3장 소개로 바꾼 것이라 PRD의 "아바타 프리셋 선택"과 다르다. 되돌리기 쉽게 캐러셀 구조는 그대로 두었다.)
- **홈**: 큰 아바타(몽실이 전신, 날씨 모습) + 말풍선(오늘·이번 주 예보 한 줄) + 날씨 UI 주간 스트립 + 다가오는 이벤트 예보 카드 + (이벤트 종료 시) 체크인 카드. 보상/적립 UI는 없다. 배경은 일정·컨디션 예보(맑음/흐림/소나기)에 따라 부드럽게 달라지는 그라데이션이고, 몸의 변화를 표현하지 않는다.
- **예보** (목록 / 등록 / 결과): 이벤트 목록, 이벤트 등록, 시뮬레이션 결과(표시체중 vs 실제지방 이중 그래프).
- **기록** (P1): 지난 이벤트 타임라인(이벤트·예보·체크인 여부). "이벤트 대응 경험" 누적 표시는 P2.
- **마이페이지**: 프로필, 아바타 꾸미기, 설정.
- **체크인**: 재개 준비도 체크인. 홈 카드와 예보 상세에서 진입한다.

## UI Rules
- Use clear button text.
- Use labels for inputs.
- Use semantic headings.
- Avoid icon-only actions (뒤로·닫기 등 표준 이동 아이콘은 예외, 접근성 라벨 필수).
- Avoid random design changes.
- 체중/신체 변화를 외형 이미지로 직접 보여주지 않는다 (아바타는 표정·소지품으로만 반응).

### 카피 톤
- 해요체, 짧은 문장.
- 비난·죄책감 없음.
- 재도전을 "실패"라 부르지 않는다.
- 수치는 "약"·범위 표현을 쓴다.
