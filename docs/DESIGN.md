# DESIGN.md

## Design Goal
반복되는 다이어트 실패에 지친 사용자에게 부담을 주지 않는, 차분하고 신뢰감 있는 모바일 앱 화면.

## Brand
- 이름: **Bodycast** (Body + Forecast). 기존 "날씨예보" 은유를 그대로 잇는다.
- 재도전을 해도 그 전의 과정은 실패가 아닌 기록으로 남는다.
- 일정이 있는 날, 몸무게를 예측할 수 있도록 AI 시뮬레이션을 제공한다 (내부 메시지. 화면에는 "예보"라는 표현을 쓴다).
- 내 아바타와 함께 성장한다.

## Visual Tone
- Calm (경쟁·보상 요소 없이 잔잔하게)
- Friendly
- Soft 3D-like
- Sky-blue — 하늘·날씨 은유와 연결되는 블루 계열을 주조색으로 삼는다
- Minimal
- Easy to scan
- Card-based when useful
- "날씨예보" 은유 — 체중 변화를 날씨처럼 자연스러운 변동으로 표현

### 레퍼런스 요약 (이미지 우선, 아래는 요약)
- 캐릭터가 화면의 주인공이다. 홈은 "큰 캐릭터 + 말풍선 + 아래 카드" 구성 (동네 걷기 앱 홈 유형)
- 대화형 온보딩: 큰 질문 한 줄 → 캐릭터 → 하단 고정 전체폭 버튼 하나. 진행 표시는 상단 원형/점 (아바타 선택 화면 유형)
- 캐릭터는 2~3등신의 부드러운 3D 느낌이고, 흰색·파스텔 바탕에 선명한 블루가 포인트다
- 배경은 부드러운 그라데이션/일러스트 (해 질 녘 보랏빛, 파란 스튜디오 등)
- 아바타 꾸미기: 상단 실시간 미리보기 + 카테고리 탭(얼굴형, 헤어, 표정, 의상 등) + 선택 테두리가 있는 그리드 + 우상단 "완료"
- 큰 라운드 카드, 큰 숫자, 넉넉한 여백, 하단 전체폭 라운드 버튼

**가져올 것**: 위 레이아웃 문법과 둥글고 부드러운 캐릭터 느낌

**가져오지 않을 것**:
- 코인·포인트·보물상자·"받기" 버튼 같은 보상/적립 구조 (기존 "경쟁·보상 없음" 원칙이 우선)
- 걸음 수·랭킹 같은 수치 압박 요소
- 레퍼런스의 캐릭터·로고·일러스트를 그대로 따라 그리는 것 (톤만 참고하고 캐릭터·에셋은 자체 제작)

### 디자인 토큰 초안 [가정] — 구현 전 최종 승인 필요
- Primary `#7FB3FF` (연한 파스텔 블루)
- Background `#FFFFFF` / Section 배경: 파스텔 블루·라벤더 그라데이션
- Text `#2B2B33` / Sub Text `#8A8F98`
- Accent (CTA): 소프트 코럴 `#FF8B6B` — 절제된 포인트로만 사용, 보상 프레임이 아님
- Radius: Card 28~32px / Button pill(전체 둥근형) / Input 20px
- Shadow: 거의 없음, flat에 가까운 느낌
- Typography: 둥근 산세리프 계열(예: Pretendard), 본문 대비 큰 크기감. 구체적인 px 스케일은 구현 세션에서 확정한다

## Mobile
- 기준 화면 390×844, 지원 폭 360~430px, 세로 고정. 상태바와 홈 인디케이터는 OS 영역이라 그리지 않는다.
- 세이프에어리어 처리: `viewport-fit=cover`와 `env(safe-area-inset-*)`를 쓴다. 하단 탭바와 하단 고정 버튼이 홈 인디케이터를 가리지 않는다.
- 화면 높이는 `100vh` 대신 `dvh`를 쓴다 (모바일 브라우저 주소창 대응).
- 터치 영역은 최소 44×44px. 주요 행동 버튼은 엄지가 닿는 하단에 전체폭으로 둔다.
- 입력 필드 글자는 16px 이상 (iOS Safari 자동 확대 방지). 숫자 입력은 숫자 키패드(`inputmode`)를 쓰고, 키보드가 올라와도 입력창과 버튼이 가려지지 않게 한다.
- 확대/축소를 막지 않는다 (접근성).
- hover에 의존하지 않는다. 탭·스와이프·바텀시트 중심이다 (아바타 캐러셀은 스와이프 + 점 표시).
- 이중 그래프는 폭 약 350px에서도 가로 스크롤 없이 읽히게 하고, 값은 탭으로 확인한다. 그래프 글자는 12px 이상.
- 애니메이션은 가볍게 하고 `prefers-reduced-motion`을 존중한다.
- 뒤로(‹)·닫기(×) 같은 표준 이동 아이콘은 "icon-only 금지" 규칙의 예외로 허용하되 접근성 라벨을 필수로 한다. 나머지 액션은 기존대로 텍스트 라벨을 쓴다.
- "홈 화면에 추가"(PWA manifest)는 P2. 서비스워커·오프라인 기능은 만들지 않는다.

## Character & Avatar Rules
- 캐릭터는 하나(내 아바타)이고, 표정·자세·말풍선·소지품으로만 반응한다. 별도 마스코트는 만들지 않는다.
- 아바타 외형은 체중·시뮬레이션 결과와 무관하게 고정이다. 체형·체중 관련 옵션은 없고(몸 실루엣 1종 고정), 커스터마이징은 얼굴형·헤어·피부톤·표정·의상·소품만 허용한다.
- 구현은 2D 레이어 합성(SVG/PNG)이다. 3D 라이브러리는 쓰지 않는다 (불필요한 의존성 추가 금지 원칙). 에셋은 자체 제작하고, 그 전까지는 플레이스홀더를 쓴다.
- 말풍선 문구는 docs/LLM.md의 안전 규칙을 따른다.

## Navigation
하단 탭바 (아이콘과 텍스트 라벨을 항상 함께 표시):
- 홈
- 예보: 이벤트 등록 → 시뮬레이션 결과(이중 그래프)를 담는다. 화면 카피에는 "AI 시뮬레이션"이라는 표현을 쓰지 않는다
- 기록 (P1): 지난 이벤트 타임라인과 "이벤트 대응 경험". 재도전을 실패가 아닌 기록으로 남기는 브랜드 메시지를 담당한다
- 마이페이지: 프로필, 아바타 꾸미기, 설정

- 재개 체크인은 별도 탭 없이, 이벤트 종료 후 홈 카드와 예보 상세에서 진입한다.
- 탭바 단계: P0는 홈·예보·마이페이지 3개, P1에서 기록 탭을 추가한다.
- 노출 규칙: 탭바는 탭 최상위 화면에서만 보이고, 온보딩·이벤트 등록·결과·체크인 같은 하위 흐름에서는 숨긴다.
- 하단 고정, 세이프에어리어 반영.

## Screens
- **스플래시/인트로**: 로고 + "시작하기" 버튼. 기존 "랜딩 페이지"를 대체한다.
- **정보 입력**: 닉네임, 재도전 횟수(N차) 필수. 키, 현재 체중은 선택.
- **아바타 설정**: 프리셋 캐러셀(스와이프 선택) → 꾸미기로 진입. 아바타를 만든 뒤 홈으로 들어가고, 이후 앱 전체에서 이 아바타가 등장한다.
- **홈**: 큰 아바타 + 말풍선(오늘·이번 주 예보 한 줄) + 날씨 UI 주간 스트립 + 다가오는 이벤트 예보 카드 + (이벤트 종료 시) 체크인 카드. 보상/적립 UI는 없다. 배경은 일정·컨디션 예보(맑음/흐림/소나기)에 따라 부드럽게 달라지는 그라데이션이고, 몸의 변화를 표현하지 않는다.
- **예보** (목록 / 등록 / 결과): 이벤트 목록, 이벤트 등록, 시뮬레이션 결과(표시체중 vs 실제지방 이중 그래프).
- **기록** (P1): 지난 이벤트 타임라인, "이벤트 대응 경험" 누적.
- **마이페이지**: 프로필, 아바타 꾸미기, 설정.
- **체크인**: 재개 준비도 체크인. 홈 카드와 예보 상세에서 진입한다.

## UI Rules
- Use clear button text.
- Use labels for inputs.
- Use semantic headings.
- Avoid icon-only actions (뒤로·닫기 등 표준 이동 아이콘은 예외, 접근성 라벨 필수).
- Avoid random design changes.
- 체중/신체 변화를 외형 이미지로 직접 보여주지 않는다 (아바타는 표정·소지품으로만 반응).

### 카피 톤
- 해요체, 짧은 문장.
- 비난·죄책감 없음.
- 재도전을 "실패"라 부르지 않는다.
- 수치는 "약"·범위 표현을 쓴다.
