# LLM.md

## 1. 역할 분담

계산은 코드가 담당한다 (docs/SIMULATION.md 기준). LLM은 아래 4가지 문구 생성만 담당한다:

- 시뮬레이션 결과 해석
- 이벤트 전/후 식단 가이드
- 재개 준비도 체크인 코칭 메시지
- 일탈 리프레이밍 메시지

LLM은 수치를 계산하거나 수정하지 않는다. 코드가 계산한 값(docs/SIMULATION.md 기준)을 입력으로 받아 그대로 인용만 한다.

## 2. 연동 규칙

CLAUDE.md의 "LLM API 1개만" 제약을 준수한다.

- 서버 API 라우트 1개(`/api/coach`)를 통해서만 LLM을 호출한다. 브라우저에서 직접 호출하지 않는다.
- API 키는 `.env.local`에만 두고 `.gitignore`에 포함한다 (`NEXT_PUBLIC_` 접두사 금지). 저장소에는 변수 이름만 적은 `.env.example`을 둔다.
- Next.js 초기화 시 생성된 `.gitignore`에 `.env*.local`이 이미 포함되어 있는지 먼저 확인한 뒤 키를 넣는다.
- 모델 이름은 코드에 하드코딩하지 않고 환경변수로 뺀다.
- 응답은 정해진 형식(JSON, 문구 필드)으로 받는다. 파싱 실패·타임아웃·API 오류 시 미리 정해둔 고정 문구로 대체해서 데모가 멈추지 않게 한다.
- LLM에 보내는 데이터는 계산에 필요한 수치만 보내고, 이름 등 식별정보는 제외한다.
- LLM 공급자: **고정 템플릿 우선 + 무료 티어 LLM 선택 연동** [2026-09-24 변경 — "무료/무결제만" 조건, docs/IMPLEMENTATION-PLAN.md 1장]. 기본은 `src/lib/coach.ts` 템플릿이고, `COACH_LLM_PROVIDER`(groq | gemini)·`COACH_LLM_API_KEY`·`COACH_LLM_MODEL`이 모두 있을 때만 `/api/coach`가 LLM을 부른다. 이전 결정(Anthropic Claude API)은 카드 없는 무료 티어가 없어 보류.

## 3. 안전 규칙

기획서의 섭식장애 위험을 고려한다 (식단 추적 앱 단독 사용자군 섭식장애 점수 79.44 vs 비사용자 68.89 [확정]). 프롬프트와 코드 양쪽에서 아래를 지킨다.

- 극단적 칼로리 제한·단식·굶기를 권유하지 않는다. 이벤트 전 "미리 덜 먹기"도 권유하지 않는다 (버퍼 식단 = 평소 식사 유지 + 균형).
- "먹은 만큼 운동으로 태우기" 같은 보상·벌칙 프레임을 쓰지 않는다. 구토·설사약·이뇨제 등 배출 행동은 언급도 권유도 하지 않는다.
- 체형·외모·몸무게에 대한 평가를 하지 않는다 ("살쪘다", "관리가 필요한 몸" 등 금지). 체중 변화는 "일시적 변동"으로만 설명한다.
- 음식을 좋은/나쁜 음식으로 도덕화하지 않고, 죄책감·비난 어조를 쓰지 않는다. 재도전 횟수를 "실패"라고 부르지 않는다 ("이벤트 대응 경험"으로 표현).
- 의사·영양사의 진단·치료·처방을 대신하지 않는다는 고지를 포함한다.
- 위험 신호(폭식-절식 반복, 배출 행동, 극심한 자기비난, 체중·체형에 대한 과도한 집착, 자해·자살 암시)가 사용자 입력에서 보이면 코칭·다이어트 플랜 생성을 멈추고, 공감하는 문구와 전문가·상담 기관 안내로 전환한다. 구체적인 연락처는 임의로 적지 않고 "[확인 필요]"로 표시해 둔다.

## 4. 범위

이번 문서는 규칙만 정리한다. 실제 LLM 프롬프트 문구는 이 문서를 근거로 구현 세션에서 작성한다.
